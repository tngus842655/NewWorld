# 건물 효과 구현 계획

건물 38종 중 **효과가 코드에 붙어 있는 것**과 **아직 짓기만 되는 것**(`planned: true`)을
정리하고, 붙이는 순서를 정한다.

순서는 **(체감 가치 ÷ 새로 필요한 시스템의 크기)** 기준이다. 기존 시스템에 바로 꽂히는
것부터 하고, 새 시스템을 통째로 만들어야 하는 것(PvP 방어전·연맹)은 뒤로 뺐다.

## 이미 붙어 있는 효과

| 건물 | 효과 | 붙은 곳 |
| --- | --- | --- |
| 채굴장·제련소·보급창·가스 추출기·거래소 | 자원 생산 | `tick.ts` settle |
| 정제소 4종·발전소 | 자원 산출 +%/레벨 (`boosts`) | `tick.ts` settle |
| 병영 | 병종 등급 해금 (`tier ≤ 레벨`) | `actions.startTraining` |
| 연구소 | 병종 연구 상한 (`레벨 × 2`) | `actions.startResearch` |
| 용병 사무소 | 지휘관 보유 한도 = 레벨 | `actions.hireHero` |

## 효과 데이터 모델 (S0)

수치는 코드가 아니라 `data/buildings/base.json`이 들고 있다.

```jsonc
"effects": [{ "kind": "armyPdefPercent", "perLevel": 4 }]
```

- `BuildingDef.effects: BuildingEffect[]` — 한 건물이 여러 효과를 가질 수 있다
- `core/city.ts`의 `buildingEffect(state, defs, kind)`가 전 건물을 훑어 합산한다
  (레벨 × perLevel). 새 효과를 붙일 때 **읽는 쪽 한 군데만** 손대면 된다
- 화면은 `BUILDING_EFFECT_LABELS`로 자동 표기 — 건물 카드에 효과가 그대로 뜬다
- 효과가 붙으면 그 건물의 `planned: true`를 뺀다 = "효과 미구현" 배지가 사라진다

### S1 실측 (튜닝 대상)

같은 조건 300회 평균으로 재 본 결과, 효과는 정확히 먹지만 **방어 쪽 체감이 작다**.

- 경험치(훈련장 Lv.5 = +30%): 150 → 195. 데이터 그대로 반영 ✅
- 방어(병기고+방어막 Lv.5 = +20%): 손실 9기 → 8기, +80%까지 올리면 7기 → 5기.
  **손실 대비로는 10~30% 감소**지만 절대 수치가 작아 눈에 잘 안 띈다.

원인은 피해 공식 `공격² / (공격 + 방어)`이 방어 증가에 둔감하기 때문.
전투 밸런스를 손볼 때 (a) `perLevel`을 올리거나 (b) 방어 건물을 '받는 피해 −%'로
따로 모델링할지 정해야 한다. 지금은 장비와 같은 경로(방어 스탯 배율)로 두었다.

### S2 판정 규칙 (estimate)

- **승리한 전투에서만** 부상병을 수습한다. 전장을 확보해야 실어 올 수 있다는 해석이고,
  원작 医疗帐篷의 조건은 자료가 없다. 패배 시 복귀 0을 테스트로 고정해 두었다.
- 복귀 수는 `floor(전사자 × 비율)`. 손실이 적으면 내림 때문에 0이 되는 게 정상이다
  (예: 전사 7기 × 10% = 0기, × 25% = 1기).
- 리포트의 `attackerLosses`는 **복귀분을 뺀 순손실**이고, 복귀분은 `recovered`로 따로 남아
  전투 기록에 `🚑 부상 복귀`로 표시된다. `순손실 + 생환 + 복귀 = 출정 병력`이 항상 성립한다.

### S3 규칙

- 기본 출정 1부대 + 전술 지휘소 레벨당 1 (`BASE_MARCH_SLOTS`, 상한 `MAX_MARCH_SLOTS = 10`).
- **한 지휘관은 한 부대만** 이끈다. 이미 나간 지휘관은 선택 칩이 '출정중'으로 잠긴다.
- **같은 목적지로 두 부대**를 동시에 보낼 수 없다 (전투 결과가 출정 시점에 미리
  계산되는 구조라, 같은 곳을 동시에 치면 결과가 겹친다).
- 부대마다 귀환 시각이 따로 돌고, 상단 큐·월드맵 경로선도 부대 수만큼 그려진다.

### S4 규칙

- **차원문**: `행군시간 × (1 − 단축률)`, 레벨당 6%, `MAX_MARCH_CUT = 60%` 상한.
  장비의 신행 목걸이(속도 증가, 나눗셈)와는 계산 축이 달라 따로 곱한다.
- **관제탑**: 출정 전 같은 전투를 9회 돌려 승산을 뽑는다(`previewBattle`).
  Lv.1~2는 승산만, **Lv.3부터 예상 손실**까지. 같은 조건이면 캐시해서 매 틱
  숫자가 흔들리지 않게 했다.
- 승산이 100%/0%로 갈리는 구간이 넓다 — 전투가 치명타 말고는 결정적이라
  그렇다. 판정 문구(무난/접전/위험/승산 없음)는 밸런스가 부드러워지면 살아난다.

### S5 규칙

- 기본 한도 `BASE_STORAGE = 50,000` + 창고 레벨당 50,000.
- **한도는 생산에만 건다.** 이미 한도를 넘겨 들고 있어도 깎지 않고, 전리품도 한도를
  넘겨 들어온다 — 벌어 놓은 것을 빼앗기지 않는 쪽으로 정했다.
- 한도에 닿은 자원은 상단 바에서 붉은 ▲로 표시된다.

### S6 규칙

유닛 데이터에 `branch`(보병/기갑/항공)를 넣고, **담당 건물 안에서의 순번**을 요구 레벨로 쓴다.
병종이 늘거나 계열이 바뀌어도 규칙이 저절로 따라온다.

| 계열 | 담당 건물 |
| --- | --- |
| 보병 1~3계 | 병영 |
| 보병 4계 이상 | 고급 병영 |
| 기갑 | 기갑 공장 |
| 항공 | 우주항 |

배정 결과 — 연합 `1i 2i 3a 4i 5a 6v 7a 8v` / 성단 `1i 2i 3i 4a 5i 6v 7a 8v` /
군체 `1i 2i 3i 4i 5i 6v 7a 8v`.

> ⚠️ **밸런스 숙제**: 연합은 3계(정찰비행체)가 항공이라, 우주항까지 가는
> 긴 건축 트리(연구소→발전소→기갑공장→가스정제탑→우주항)를 타야 한다.
> 종족별 초반 전력 차이가 크게 벌어지므로, 우주항·기갑공장의 `requires`를
> 낮추거나 저계 유닛의 계열을 손볼 것.
